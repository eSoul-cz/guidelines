# Project guidelines - Frontend

## Stack

The pages are Inertia with Vue 3 and TypeScript, with Laravel Wayfinder for routes, shadcn-vue for
the design system's primitives and Vitest for frontend tests, on top of the Vite and Tailwind CSS
setup above. The rules for components, TypeScript, Inertia data flow, forms and frontend tests are
in the Vue sections of this file.

## Project structure and locality

```text
resources/js/
├── pages/            # Inertia page entry points and their branch-local code
├── design-system/    # domain-independent public UI (App* components)
│   ├── ui/           # private shadcn-vue and vendor-like primitives
│   └── index.ts      # curated public exports
├── components/       # components reused by several page branches
├── layouts/          # persistent and route-level layouts
├── composables/      # globally reusable reactive behaviour
├── utils/            # globally reusable pure functions
├── model/            # globally reusable frontend model classes
├── payload/types.ts  # globally shared backend transport contracts
├── types.ts          # globally shared frontend-only types
└── actions/ routes/ wayfinder/   # generated by Wayfinder, never edited
```

- Code MUST start in the page branch that owns it. Its components, composables, utils, models,
  payload contracts and types live directly below that branch.
- Per-page directories such as `Index/components` MUST NOT be introduced; a branch-level
  `components` directory is used even with one consumer.
- Code moves to a global location only when it has consumers in **separate page branches**, and
  only as far outward as needed. Moving code outward "because it might be reused" is prohibited;
  brief duplication is fine until real consumers show the shared boundary.
- Reuse alone does not make a component part of the design system (see below).
- No `components/shared` and no generic `lib` directory. `utils` holds stateless functions only;
  reactive or lifecycle-aware behaviour is a composable.
- Global modules MUST NOT import from `pages`. Imports outside the current branch use `@/`.
- Hand-maintained directories use kebab-case; the generated Wayfinder directories keep the names
  the generator produces. Renaming an Inertia page path updates the `Inertia::render()` name in
  the same change.

```text
pages/catalog/products/components/ProductSummary   one page branch
          │ reused by another branch
          ▼
components/ProductSummary                          several branches
```

## Inertia server side

- A controller returns `Inertia::render('<branch>/<Page>', [...])`. The component name is the
  page's path under `resources/js/pages`, with the same casing.
- Page props come from the DTOs queries return ([cqrs.md](cqrs.md#writing-queries)), mapped by a
  JSON resource or the DTO itself. An Eloquent model is never passed as a prop.
- Props are minimal and serializable and carry only what the acting user may see. Hiding data in
  the browser is not authorization: sensitive attributes never reach the response. Abilities the
  page needs (can edit, can delete) are sent as booleans computed by the policy.
- Numbers, amounts and dates are formatted on the server ([domain.md](domain.md#money)); the
  frontend renders the string it receives.
- Shared data (`HandleInertiaRequests`) holds only what every page needs: the acting user's
  public fields, abilities, flash messages and locale. It never holds a large or per-page
  collection.
- Expensive secondary data uses deferred props (`Inertia::defer()`); large datasets are filtered
  and paginated on the server, never shipped whole.
- Mutations validate in a form request and redirect afterwards (`back()` or `to_route()`);
  validation errors and flash messages reach the page through Inertia's shared errors and flash
  data, never as a hand-built JSON error. Page props, errors and flash keys are a contract tested
  by Laravel feature tests with `assertInertia()` ([testing.md](testing.md#controller-testing)).
- An inline script in a Blade view carries `nonce="{{ Vite::cspNonce() }}"`. A third-party script
  or a request to another origin adds its origin to the Content Security Policy in the same
  change.
- Page behaviour on the client (forms, navigation, loading states) is in the Vue sections of this
  file.

## Routes and Wayfinder

- Every Laravel route or controller action the frontend calls goes through generated Wayfinder
  functions, imported by name from `@/actions` or `@/routes`. Application URLs are never
  hardcoded.
- Pass a Wayfinder route object directly where Inertia accepts it; use `.form()` for form
  components and `.url()` only when a string URL is required. Route-model-binding parameters use
  their typed Wayfinder form instead of interpolating ids into paths.
- `resources/js/actions`, `resources/js/routes` and `resources/js/wayfinder` are generated by the
  Vite plugin during `pnpm dev` and `pnpm build`, and are never edited. After a backend route
  change with the plugin unavailable, run `php artisan wayfinder:generate --with-form`, which also
  generates the `.form()` variants.

## Design system

- `resources/js/design-system` is the domain-independent public UI module. Pages, layouts and
  application components consume it only through the curated entry point `@/design-system`.
- **Public design-system components use the `App` prefix** (`AppButton`, `AppTable`). Private
  primitives in `design-system/ui` are imported only inside the design system, with the `Ui`
  prefix (`Button as UiButton`). Application code MUST NOT import a `Ui` primitive.
- An unchanged primitive MAY be exported with an `App` alias
  (`export { Button as AppButton } from './ui/button'`). A dedicated `App` component is created
  only when it narrows the API, sets application-wide variants or composes primitives; a component
  that only forwards everything is not created.
- The design system MUST NOT import pages, application components, models, payload contracts,
  Wayfinder or Inertia, and contains no domain names, rules, routes or copy.
- **shadcn-vue** primitives (built on Reka UI) are added with its CLI into
  `@/design-system/ui`; `components.json` aliases point there and `cn()` comes from
  `@/utils/classes`. Private primitives change only for upstream sync, accessibility, security,
  correctness or a deliberate design-system-wide change.
- A new visual pattern starts in its page branch and is promoted once its domain-independent
  contract is clear and real reuse justifies it.
- Icons come from the project's icon package (`@lucide/vue`); how they are imported is in the Vue
  sections of this file.

### Accessibility ownership

- The design system owns keyboard interaction, focus management, visible focus, ARIA relations
  and the disabled, loading, invalid, empty, success and failure states of reusable controls.
  Application code never rebuilds them.
- The consuming page provides labels, descriptions, errors, headings and alternative content.
- Colour is never the only carrier of a state. Buttons are for actions, links for navigation.
  Decorative icons are hidden from assistive technology; icon-only controls have an accessible
  name.

## Tailwind CSS

- A colour that carries domain meaning (a status, a category) is a named semantic token with light
  and dark values, and one application component owns the mapping from the domain value to it.
  Pages never apply raw palette classes or borrow an unrelated token.
- Utility classes live primarily in design-system components. Outside them, utilities are for
  route-level layout, responsive placement and genuinely local presentation; repeated class groups
  are a signal of a missing component, variant or token.
- Consumers never override a design-system component's internals with classes; add a variant,
  size or slot to the public component, or place it with a surrounding layout element.
- Use `cn()` from `@/utils/classes` for conditional classes. Prefer `gap` over sibling margins.

## Vite and bundling

- The Wayfinder plugin runs next to the Laravel plugin in Vite.
- Every module a page imports statically is preloaded, and Laravel repeats it in the `Link`
  response header. Large pages can exceed a proxy's header limit (a load balancer may accept only
  about 15 kB) and fail with a 502, so keep each page's static module graph small and cap the
  number of preloaded assets in `bootstrap/app.php` as a safety net, not a budget. The proxy's
  buffers are in [deployment.md](deployment.md#reverse-proxy-and-tls).
- Code MUST NOT pull a whole library into a shared chunk through a namespace import, a re-exported
  map or a lookup by name; import specific exports so tree-shaking works.
- Chunk grouping lives in `build.rolldownOptions.output.codeSplitting.groups` in `vite.config.ts`.
  Do not add groups without measuring the number of preloaded assets and the gzipped size of
  typical pages. After changing imports in a page or shared module, check the entries in
  `public/build/manifest.json` reachable through `imports`; a sharp increase points to a static
  import that should be lazy or more specific.

## Frontend commands

```bash
pnpm dev           # Vite dev server (generates the Wayfinder modules)
pnpm build         # production build
pnpm eslint        # ESLint flat config, read-only
pnpm format:check  # Prettier (printWidth 150, tabWidth 4), read-only
pnpm tsc           # type check
pnpm test          # Vitest
pnpm eslint:fix && pnpm format   # explicit autofix, review the diff
```

- The read-only commands are what CI runs ([deployment.md](deployment.md#pipeline)); the autofix
  commands (`eslint:fix`, `format`) are developer actions
  ([tools.md](tools.md#formatting-and-lint-autofixes)).
